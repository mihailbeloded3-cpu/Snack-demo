# Gift Sniper — план

Софт следит за маркетами подарков Telegram, сравнивает новые лоты с флором
(коллекция + модель + фон) и присылает уведомление в Telegram, если лот
дешевле рынка. **Только уведомления, без автопокупки.**

## Решения
| Параметр | Значение |
|---|---|
| Маркеты | Portals, MRKT (позже можно добавить другие) |
| Где работает | Сначала на своём компьютере, потом VPS |
| Что отслеживать | Задаёт пользователь: все коллекции или список коллекций / моделей / фонов |
| Фильтры | Мин. скидка %, мин. прибыль TON, мин./макс. цена лота (например, не дороже 100 TON) |
| Покупка | Вручную по ссылке из уведомления |

## Источники данных
Официальных API нет. Используем внутренние API мини-приложений
(через них же работают open-source библиотеки `faportalsmp` и `tgmrkts`).

**Portals** (`portal-market.com/api/`, авторизация initData Telegram, нужен
`curl_cffi` из-за Cloudflare):
- `nfts/search?sort_by=listed_at+desc` — новые лоты, есть фильтр по цене
- `market/actions/` — лента событий (листинги, продажи)
- `collections/models/backgrounds/floors` — флоры по модели и фону

**MRKT** (`api.tgmrkt.io/api/v1/`, авторизация токеном через Telegram):
- `feed` с `type=["listing","change_price"]`, `ordering=Latest` — новые лоты и снижения цены
- `gifts/saling` с фильтрами модель/фон/цена — для расчёта флора

## Как ловим все новые лоты
Весь маркет каждый раз не сканируем. Каждые 2–3 с запрашиваем первую
страницу ленты «сначала новые» (20–50 лотов) и останавливаемся на первом
уже виденном ID. Если за цикл пришло больше страницы, догружаем следующую.
Фильтр по цене (`max_price`) передаём прямо в запрос.

## Оценка цены
1. Флор комбинации «модель + фон» = минимум по Portals и MRKT.
2. Если лотов в комбинации меньше 3 — берём 2-ю цену и учитываем недавние продажи.
3. Нет данных — фоллбэк: флор модели → флор фона → флор коллекции.
4. Комиссии маркетов вычитаем.
5. `прибыль = флор × (1 − комиссия продажи) − цена`.
   Сигнал, если `прибыль ≥ min_profit` и `скидка ≥ min_discount`.
6. Флоры пересчитываются в фоне раз в 1–5 мин, только по отслеживаемым коллекциям.

## Пример настроек (`config.yaml`)
```yaml
min_price_ton: 1
max_price_ton: 100
min_discount_pct: 15
min_profit_ton: 2
poll_interval_sec: 2
watch: all            # или список ниже
# watch:
#   - collection: "Plush Pepe"
#     models: []      # пусто = любые
#     backdrops: ["Black", "Onyx Black"]
```
Те же параметры меняются командами в боте: `/max_price 100`, `/min_discount 15`, ...

## Стек
Python 3.12, asyncio, `curl_cffi`/`aiohttp`, Telethon (вход в Telegram и
получение initData), aiogram (бот-уведомления), SQLite.

## Этапы
0. **Разведка (на компьютере)** — готово, `recon.py`: скрипт тянет новые лоты с Portals и MRKT,
   выясняем реальный максимум размера страницы, лимиты запросов и сколько
   новых лотов появляется в минуту.
1. **Флоры:** расчёт флора по модели и фону с обоих маркетов.
2. **Уведомления:** бот присылает сделки с фото, ценой, флором, % и ссылкой.
3. **Настройки через бота** + фильтры по коллекциям/моделям/фонам.
4. **Переезд на VPS** + отдельный Telegram-аккаунт.

## Вложения
- Тест на компьютере: **0 ₽** (Python, бот от @BotFather, api_id с my.telegram.org — бесплатно).
- Позже: VPS ~5 $/мес, отдельный аккаунт (SIM/номер) ~100–300 ₽ разово.
- Плюс собственный оборотный капитал на покупку подарков.

## Риски
- Внутренние API могут измениться без предупреждения — коннекторы придётся чинить.
- Частые запросы с основного аккаунта — небольшой риск ограничений;
  для теста ок, для постоянной работы — отдельный аккаунт.
- Флор по редким комбинациям ненадёжен — нужна проверка ликвидности.
